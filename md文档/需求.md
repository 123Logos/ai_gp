# AI 陪伴与智能提醒 App 技术设计文档

## 1. 项目概述
本项目旨在构建一款具备人格化交互能力的 AI 陪伴应用，核心功能为在与 AI 自然对话的过程中实现**每日事项提醒**，并根据用户行为逐步构建深度用户画像。支持用户使用官方提供的 AI 服务，也可自行填入第三方 API Key，实现灵活调用。

## 2. 核心功能
- **自然语言对话提醒**：AI 在聊天中主动或按需提醒用户待办任务，支持重复、延时、提前提醒。
- **多端设备安全管理**：新设备首次登录强制验证码，信任设备可免验证登录。
- **灵活 API 调用策略**：支持平台官方模型、用户自有 API Key，以及按供应商路由。
- **用户认证体系**：手机号、邮箱及第三方登录（微信/Apple/Google），支持多方式绑定。
- **任务全生命周期管理**：创建、完成、取消任务，AI 可从对话中提取任务。
- **用户性格洞察（后期）**：从对话中分析情绪、兴趣、行为模式，形成可解释的用户画像。

## 3. 技术栈概述
- **后端**：Node.js / Go / Python（任一高性能框架）
- **数据库**：MySQL 8.0+ 或 PostgreSQL（本设计以 MySQL 语法呈现）
- **缓存**：Redis（验证码、会话热数据）
- **消息推送**：FCM / APNs 结合定时任务调度
- **安全**：AES-256-GCM 加密敏感字段，Argon2 密码哈希，JWT + Refresh Token 机制

## 4. 数据库设计

### 4.1 表关系总览
```
users (1) ─< (N) user_identities
users (1) ─< (N) user_sessions
users (1) ─< (N) user_api_keys
users (1) ─< (N) tasks ─< (N) task_reminders ─< (N) reminder_logs
users (1) ─< (N) conversations ─< (N) messages
users (1) ─  user_preferences (1:1)
verification_codes (独立)
insight_extractions (关联 users)
```
共计 10 张表，按模块分为：
- 用户体系：`users`, `user_identities`, `user_sessions`, `user_preferences`, `user_api_keys`, `verification_codes`
- 任务体系：`tasks`, `task_reminders`, `reminder_logs`
- 对话体系：`conversations`, `messages`, `insight_extractions`

## 5. API 调用路由逻辑
后端通过 `user_preferences` 表来决定调用哪个 AI 服务的 API。

**判定流程**：
1. 根据 `user_id` 查询 `user_preferences.ai_provider`。
2. 若为 `official` → 使用部署在服务器环境变量中的官方 API Key。
3. 若为 `custom` → 检查 `preferred_key_id` 是否存在且 `is_enabled=1` 且 `is_valid=1`：
   - 存在：解密该 key，用于本次调用。
   - 不存在：获取该用户所有 `is_enabled=1` 的有效 key，取最近更新的一个。
4. 调用前校验 key 有效性（签名或小额度请求），失败则标记 `is_valid=0` 并降级或报错。
5. 调用结果及用量写入日志（不计入明文密钥）。

前端可供用户在设置界面切换“使用官方服务”或“使用我的 API Key”，并可管理多组 Key 的启用/禁用。

## 6. 关键业务流程

### 6.1 新设备登录验证
1. 客户端生成设备唯一 `device_id`（存储在 Keychain/Keystore）。
2. 用户输入手机号/邮箱 + 密码或第三方授权。
3. 服务端查询 `user_sessions` 是否存在 `user_id + device_id` 且 `is_trusted=1`：
   - **是**：直接登录，创建新 session，替换 `refresh_token`，继承信任状态。
   - **否**：触发验证码流程 (`scene='trust_device'`)。
4. 用户输入验证码，验证成功后：
   - 在 `user_sessions` 中 upsert 记录，设置 `is_trusted=1`。
   - 同时将 `user_identities` 中该认证方式的 `verified_at` 记录。
5. 返回 JWT access token (短期) 和 refresh token。

### 6.2 智能任务提醒
1. 用户可在对话中自然表达“明天下午三点提醒我开会”，或手动创建任务。
2. 后端 NLP 模块或 LLM 提取意图，创建 `tasks` 记录及对应的 `task_reminders`。
3. 定时调度服务扫描 `task_reminders`，到达提醒时间时：
   - 查询 `user_preferences` 中的免打扰时段，判断是否静默。
   - 若允许推送，向用户设备发送本地通知或应用内消息。
   - 生成 `reminder_logs` 记录。
4. AI 在后续对话中可引用提醒状态：“您昨天的读书任务还没完成哦～”

### 6.3 用户性格洞察（后期）
1. 离线任务定期读取新产生的 `messages`。
2. 通过 LLM 批量分析对话内容，提取用户的性格特征、兴趣爱好、行为模式。
3. 将分析结果写入 `insight_extractions`，经人工或规则审核后可合并进用户画像专用缓存（或未来扩展的 `user_profiles` 表）。
4. AI 对话时加载用户画像，调整语气和回复风格。

## 7. 安全与隐私
- **传输安全**：全站 HTTPS，API 接口强制 TLS 1.3。
- **敏感数据存储**：
  - 手机号、邮箱、第三方标识、API Key 使用 AES-256-GCM 加密，密钥通过 KMS 管理。
  - 密码使用 Argon2id 哈希。
  - Refresh Token 在数据库中以 SHA-256 哈希形式存储。
- **日志脱敏**：禁止记录任何密钥、明文令牌，日志中相关字段以 `***` 替换。
- **访问控制**：数据库账号遵循最小权限原则，应用程序仅访问必要的表。
- **用户权利**：提供账号注销时自动清理个人数据；可查看、修正或删除 AI 生成的画像标签。

## 8. 扩展性说明
- **画像深度扩展**：未来可将 `insight_extractions` 落地为结构化的 `user_profiles` 表，字段包括 `personality_tags`、`behavior_patterns` 等 JSON 列，甚至引入向量字段进行相似用户匹配。
- **多模型路由**：`user_preferences.ai_provider` 和 `user_api_keys.provider` 可灵活支持接入多个 AI 供应商，通过配置层实现 A/B 测试或成本优化。
- **任务协同**：`tasks` 表可增加 `assignee_id` 等字段扩展为多人共享提醒。
