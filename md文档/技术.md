# AI 智能日程管家 (AI Planner) V1.0 - 后端技术架构与开发文档

## 1. 项目概述
本项目是一个基于大语言模型 (LLM) 驱动的智能记事本应用。核心交互模式为“对话即操作”。后端系统的主要职责是承接前端请求，与 LLM 交互，通过 **Function Calling (函数调用)** 将自然语言意图解析为具体的数据库操作（CRUD），并管理定时提醒逻辑。

**阅读对象**：后端开发工程师、AI 编程助手（Cursor / Copilot / Gemini 等）。

---

## 2. 后端技术栈说明
*   **核心框架**：Java 17+ / Spring Boot 3.x
*   **AI 编排框架**：Spring AI (用于对接大模型 API，处理 Prompt 与 Function Calling)
*   **持久层框架**：MyBatis-Plus 或 Spring Data JPA
*   **数据库**：MySQL 8.0
*   **定时任务**：Spring Boot Starter Quartz (处理主动提醒)
*   **API 文档**：SpringDoc OpenAPI (Swagger 3)

---

## 3. 核心业务流程 (Workflow)

当用户在前端输入自然语言（例如：“明天下午3点提醒我开周会”）时，后端的处理链路如下：

1.  **接收请求**：Controller 接收前端用户的 Message。
2.  **构建 Prompt**：组装上下文（历史对话记录、当前系统时间、系统提示词）。
3.  **调用 LLM**：将组装好的 Prompt 及后端注册的 **Tools (CRUD 函数)** 发送给大模型。
4.  **执行 Function Call**：
    *   LLM 根据意图决定调用 `addTask` 工具。
    *   LLM 提取参数（时间：`2026-05-12 15:00:00`，内容：`开周会`）。
    *   Spring AI 自动拦截拦截该请求，映射并执行后端本地的 `TaskService.addTask()` 方法存入 MySQL。
5.  **返回结果**：将数据库操作结果返回给 LLM，LLM 生成最终的自然语言回复返回给前端。
6.  **前端同步**：前端收到回复后，通过另外的查询接口（或 WebSocket）刷新表格视图。

## 4. 数据库设计 (MySQL)

系统 V1.0 主要涉及一张核心任务表：`ai_task`。

```sql
CREATE DATABASE IF NOT EXISTS `ai_planner_db` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

USE `ai_planner_db`;

CREATE TABLE `ai_task` (
  `id` bigint(20) NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `user_id` varchar(64) NOT NULL COMMENT '用户ID',
  `content` varchar(255) NOT NULL COMMENT '任务内容',
  `plan_time` datetime NOT NULL COMMENT '计划执行时间',
  `priority` tinyint(4) DEFAULT '0' COMMENT '优先级: 0-普通, 1-紧急',
  `status` tinyint(4) DEFAULT '0' COMMENT '状态: 0-待办, 1-已完成, 2-已取消, 3-已过期',
  `is_reminded` tinyint(1) DEFAULT '0' COMMENT '是否已提醒: 0-否, 1-是',
  `create_time` datetime DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` datetime DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  KEY `idx_user_time` (`user_id`, `plan_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='AI智能日程任务表';

## 6. LLM Function Calling 定义 (供 AI 助手编写代码参考)

在使用 Spring AI 注册 Tool/Function 时，需严格定义以下接口，以便 LLM 能够精准传入 JSON 参数：

### 6.1 `addTask` (添加任务)
*   **Description**: 当用户希望记录、添加、安排一个新的任务或日程时调用。
*   **Parameters**:
    *   `content` (String, required): 任务的具体内容。
    *   `planTime` (String, required): 任务的执行时间，格式必须为 `YYYY-MM-DD HH:mm:ss`。
    *   `priority` (Integer, optional): 0表示普通，1表示紧急。

### 6.2 `updateTask` (修改任务)
*   **Description**: 当用户要求修改已有任务的时间、内容或标记为完成/取消时调用。
*   **Parameters**:
    *   `taskId` (Long, required): 需要修改的任务的主键ID（通常 LLM 需要先调用查询函数获取 ID）。
    *   `newPlanTime` (String, optional): 新的执行时间。
    *   `newContent` (String, optional): 新的任务内容。
    *   `targetStatus` (Integer, optional): 状态变更，如改为完成(1)。

### 6.3 `queryTasks` (查询任务)
*   **Description**: 当需要确认任务状态，或在修改/删除前需要定位具体任务时调用。
*   **Parameters**:
    *   `timeRangeStart` (String, optional): 查询起始时间。
    *   `timeRangeEnd` (String, optional): 查询结束时间。
    *   `keyword` (String, optional): 任务内容关键字。

## 7. 定时提醒逻辑设计 (Quartz / Spring Scheduler)

1.  **轮询策略**：后端开启一个定时任务，每分钟扫描一次 `ai_task` 表中 `status = 0` (待办) 且 `is_reminded = 0` 且 `plan_time` 距离当前时间小于 N 分钟的任务。
2.  **消息推送**：
    *   短连接方案：记录在消息表中，前端每隔一段时间轮询获取。
    *   长连接方案（推荐）：使用 WebSocket (`Spring Boot Starter WebSocket`)，后端主动向特定 `userId` 的前端通道推送 JSON 提醒包。
3.  **状态更新**：推送成功后，将记录的 `is_reminded` 更新为 1。

## 8. 系统提示词 (System Prompt) 示例

在初始化 LLM Client 时，必须注入以下系统提示词，以规范其行为：

```text
你是一个专业的智能日程助理。当前系统时间是：{current_time}。
你的主要任务是通过对话帮助用户管理日程。
规则：
1. 必须优先使用提供的工具（Functions）来执行数据库操作，而不是仅仅口头答应。
2. 在调用时间相关工具时，必须基于当前系统时间推算绝对时间（例如：如果今天是5月10日，用户说"明天"，你必须转换为 "2026-05-11"）。
3. 如果用户的指令模糊（如缺少具体时间），请先反问用户，收集齐参数后再调用工具。
4. 工具执行成功后，请用简短、友好的自然语言向用户反馈操作结果。
