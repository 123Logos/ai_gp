## 1. 用户主表 `users`
存储用户唯一身份标识、画像数据与基础配置，不保存敏感联系方式。

```sql
CREATE TABLE users (
    id            BIGINT UNSIGNED  NOT NULL AUTO_INCREMENT COMMENT '内部主键',
    uid           CHAR(16)         NOT NULL COMMENT '对外唯一用户标识',
    nickname      VARCHAR(50)      DEFAULT NULL COMMENT '昵称',
    avatar_url    VARCHAR(500)     DEFAULT NULL COMMENT '头像地址',
    weekly_hours  TINYINT UNSIGNED DEFAULT 0  COMMENT '每周可用小时数（1-40）',
    status        TINYINT          DEFAULT 1  COMMENT '账户状态：1正常 2禁用 3注销',
    timezone      VARCHAR(50)      DEFAULT 'Asia/Shanghai' COMMENT '时区',
    language      VARCHAR(10)      DEFAULT 'zh-CN' COMMENT '语言偏好',
    created_at    DATETIME         DEFAULT CURRENT_TIMESTAMP COMMENT '注册时间',
    updated_at    DATETIME         DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '最近更新时间',
    PRIMARY KEY (id),
    UNIQUE KEY uk_uid (uid)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='用户主表';
```

### 字段说明
| 字段 | 类型 | 说明 |
|:---|:---|:---|
| `id` | BIGINT | 自增主键，内部关联用 |
| `uid` | CHAR(16) | 对外暴露的唯一标识，如 `USER202405120001` |
| `nickname` | VARCHAR(50) | 用户昵称，可修改 |
| `avatar_url` | VARCHAR(500) | 头像图片链接 |
| `weekly_hours` | TINYINT | 用户设定的每周可投入总小时，取值范围1-40，影响AI排期 |
| `status` | TINYINT | 1-正常；2-禁用；3-注销 |
| `created_at` | DATETIME | 自动记录创建时间 |
| `updated_at` | DATETIME | 自动记录最后修改时间 |

## 2. 用户认证方式表 `user_identities`
每条记录代表一种登录方式，密码与第三方令牌加密存储，支持多认证渠道绑定同一用户。

```sql
CREATE TABLE user_identities (
    id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    user_id       BIGINT UNSIGNED NOT NULL COMMENT '关联users.id',
    identity_type ENUM('phone','email','wx','apple','google') NOT NULL COMMENT '认证类型',
    identifier    VARCHAR(255)    NOT NULL COMMENT '手机/邮箱/openid等（AES-256-GCM加密存储）',
    credential    VARCHAR(255)    DEFAULT NULL COMMENT '密码哈希（仅密码登录使用）',
    is_primary    TINYINT(1)      DEFAULT 0 COMMENT '是否主要认证方式',
    verified_at   DATETIME        DEFAULT NULL COMMENT '验证完成时间',
    extra_meta    JSON            DEFAULT NULL COMMENT '第三方token等扩展信息（加密）',
    created_at    DATETIME        DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY uk_identity (identity_type, identifier),
    KEY idx_user_id (user_id),
    CONSTRAINT fk_identities_user FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='用户认证方式表';
```

### 字段说明
| 字段 | 类型 | 说明 |
|:---|:---|:---|
| `id` | BIGINT | 主键 |
| `user_id` | BIGINT | 关联用户ID，级联删除 |
| `identity_type` | ENUM | 认证类型：手机、邮箱、微信、Apple、Google |
| `identifier` | VARCHAR(255) | 认证标识，如 openid、手机号，应用层加密 |
| `credential` | VARCHAR(255) | 密码哈希，仅 identity_type 为 phone/email 时使用 |
| `is_primary` | TINYINT | 是否为主要登录方式 |
| `verified_at` | DATETIME | 该认证方式的验证通过时间 |
| `extra_meta` | JSON | 扩展信息，如微信 unionid、access_token 等 |
| `created_at` | DATETIME | 绑定时间 |

## 3. 会话与设备信任表 `user_sessions`
管理用户登录会话、设备信息及信任状态，支持多地登录与主动踢出。

```sql
CREATE TABLE user_sessions (
    id                BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    user_id           BIGINT UNSIGNED NOT NULL,
    device_id         VARCHAR(64)     NOT NULL COMMENT '客户端生成的设备唯一ID',
    platform          VARCHAR(20)     DEFAULT NULL COMMENT 'ios/android/web',
    device_name       VARCHAR(100)    DEFAULT NULL COMMENT '设备别名（iPhone 15 Pro等）',
    ip_address        VARCHAR(45)     DEFAULT NULL COMMENT '登录IP',
    refresh_token     VARCHAR(255)    NOT NULL COMMENT '刷新令牌（哈希存储）',
    access_token_jti  VARCHAR(64)     DEFAULT NULL COMMENT '当前有效JWT的唯一ID，用于黑名单校验',
    is_trusted        TINYINT(1)      DEFAULT 0 COMMENT '设备是否通过第二因素验证且信任',
    expires_at        DATETIME        NOT NULL COMMENT 'refresh token过期时间',
    created_at        DATETIME        DEFAULT CURRENT_TIMESTAMP,
    revoked_at        DATETIME        DEFAULT NULL COMMENT '主动撤销时间',
    PRIMARY KEY (id),
    UNIQUE KEY uk_user_device (user_id, device_id),
    KEY idx_refresh_token (refresh_token(100)),
    CONSTRAINT fk_sessions_user FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='会话与设备信任表';
```

### 字段说明
| 字段 | 类型 | 说明 |
|:---|:---|:---|
| `id` | BIGINT | 主键 |
| `user_id` | BIGINT | 用户ID |
| `device_id` | VARCHAR(64) | 客户端生成的设备指纹 |
| `platform` | VARCHAR(20) | 登录平台 |
| `device_name` | VARCHAR(100) | 设备名称，便于用户识别 |
| `refresh_token` | VARCHAR(255) | 加密存储的刷新凭证 |
| `access_token_jti` | VARCHAR(64) | 当前活跃 JWT 的 JTI，用于服务端主动使其失效 |
| `is_trusted` | TINYINT(1) | 设备是否受信任，可跳过部分二次验证 |
| `expires_at` | DATETIME | 会话过期时间 |
| `revoked_at` | DATETIME | 非空表示已主动注销 |

## 5. 目标表 `goals`
存储每个成长目标的基础信息、AI拆解结果与状态流转记录。

```sql
CREATE TABLE goals (
    id              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    user_id         BIGINT UNSIGNED NOT NULL,
    title           VARCHAR(200)    NOT NULL COMMENT '目标标题',
    description     VARCHAR(2000)   DEFAULT NULL COMMENT '原始自然语言描述',
    domain          ENUM('SKILLS','CERTIFICATION','LANGUAGE','SOFT_SKILLS','SIDE_HUSTLE') DEFAULT NULL COMMENT '所属领域',
    priority        ENUM('HIGH','MEDIUM','LOW') DEFAULT 'MEDIUM' COMMENT '优先级',
    deadline        DATE            DEFAULT NULL COMMENT '期望完成日期',
    status          ENUM('DECOMPOSING','PENDING','ACTIVE','PAUSED','COMPLETED','ABANDONED','NEED_DECISION') DEFAULT 'DECOMPOSING' COMMENT '目标状态',
    milestones_json JSON            DEFAULT NULL COMMENT 'AI拆解后的完整里程碑数据快照（冗余，便于快速展示）',
    progress        DECIMAL(5,2)    DEFAULT 0.00 COMMENT '完成百分比（0.00-100.00）',
    created_at      DATETIME        DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    KEY idx_user_status (user_id, status),
    KEY idx_user_priority (user_id, priority),
    CONSTRAINT fk_goals_user FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='目标表';
```

### 字段说明
| 字段 | 类型 | 说明 |
|:---|:---|:---|
| `id` | BIGINT | 主键 |
| `user_id` | BIGINT | 所属用户 |
| `title` | VARCHAR(200) | 目标核心标题，如“3个月掌握Python” |
| `description` | VARCHAR(2000) | 用户原始输入文本，保留以备复盘 |
| `domain` | ENUM | 成长领域 |
| `priority` | ENUM | 优先级，用于排期时的资源分配顺序 |
| `deadline` | DATE | 期望完成日期 |
| `status` | ENUM | 当前状态：DECOMPOSING(拆解中)、PENDING(待排期)、ACTIVE(进行中)、PAUSED(已暂停)、COMPLETED(已完成)、ABANDONED(已放弃)、NEED_DECISION(需用户决策) |
| `milestones_json` | JSON | 里程碑原始数据的冗余存储，方便直接展示 |
| `progress` | DECIMAL(5,2) | 基于已完成任务数计算的进度百分比 |

## 6. 里程碑表 `milestones`
将 AI 拆解出的阶段里程碑结构化存储，便于追踪每个阶段的完成状态与产出。

```sql
CREATE TABLE milestones (
    id              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    goal_id         BIGINT UNSIGNED NOT NULL,
    name            VARCHAR(200)    NOT NULL COMMENT '阶段名称，如“Python基础语法”',
    sort_order      INT UNSIGNED    DEFAULT 0 COMMENT '阶段顺序，从0开始',
    estimated_weeks DECIMAL(3,1)    DEFAULT 0 COMMENT '建议所需周数',
    deliverable     VARCHAR(500)    DEFAULT NULL COMMENT '关键产出描述',
    dependencies    JSON            DEFAULT NULL COMMENT '前置里程碑ID数组，如[1,2]',
    status          ENUM('PENDING','IN_PROGRESS','COMPLETED') DEFAULT 'PENDING' COMMENT '达成状态',
    completed_at    DATETIME        DEFAULT NULL COMMENT '实际达成时间',
    created_at      DATETIME        DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    KEY idx_goal_id (goal_id),
    CONSTRAINT fk_milestones_goal FOREIGN KEY (goal_id) REFERENCES goals(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='里程碑表';
```

### 字段说明
| 字段 | 类型 | 说明 |
|:---|:---|:---|
| `id` | BIGINT | 主键 |
| `goal_id` | BIGINT | 所属目标ID |
| `name` | VARCHAR(200) | 阶段名称 |
| `sort_order` | INT | 阶段顺序，用于排序展示 |
| `estimated_weeks` | DECIMAL(3,1) | AI给出的建议完成周数 |
| `deliverable` | VARCHAR(500) | 该阶段需产出的成果说明 |
| `dependencies` | JSON | 依赖的前置里程碑ID列表 |
| `status` | ENUM | PENDING/IN_PROGRESS/COMPLETED |
| `completed_at` | DATETIME | 实际达成时间，用于复盘 |

## 7. 计划版本表 `plans`
每一次排期操作生成一条版本记录，支持计划演进的完整回溯。

```sql
CREATE TABLE plans (
    id                BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    goal_id           BIGINT UNSIGNED NOT NULL,
    version           INT UNSIGNED    NOT NULL DEFAULT 1 COMMENT '计划版本号，从1递增',
    status            ENUM('ACTIVE','DEPRECATED') DEFAULT 'ACTIVE' COMMENT '版本状态',
    generated_at      DATETIME        DEFAULT CURRENT_TIMESTAMP COMMENT '排期生成时间',
    ai_prompt_version VARCHAR(50)     DEFAULT NULL COMMENT '生成该计划所用的AI Prompt版本',
    created_at        DATETIME        DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    KEY idx_goal_version (goal_id, version),
    KEY idx_goal_status (goal_id, status),
    CONSTRAINT fk_plans_goal FOREIGN KEY (goal_id) REFERENCES goals(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='计划版本表';
```

### 字段说明
| 字段 | 类型 | 说明 |
|:---|:---|:---|
| `id` | BIGINT | 主键 |
| `goal_id` | BIGINT | 所属目标 |
| `version` | INT | 递增版本号，用于切换计划 |
| `status` | ENUM | ACTIVE-当前执行版本；DEPRECATED-已被新计划替代 |
| `generated_at` | DATETIME | 本次排期完成时间 |
| `ai_prompt_version` | VARCHAR(50) | 标记使用的 prompt 版本，便于问题追溯 |

## 8. 任务表 `tasks`
存储排期后生成的每日具体任务，是用户执行与反馈的核心数据。

```sql
CREATE TABLE tasks (
    id                BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    plan_id           BIGINT UNSIGNED NOT NULL COMMENT '所属计划版本',
    goal_id           BIGINT UNSIGNED NOT NULL COMMENT '冗余，便于跨计划聚合查询',
    user_id           BIGINT UNSIGNED NOT NULL COMMENT '冗余，快速权限校验',
    milestone_id      BIGINT UNSIGNED DEFAULT NULL COMMENT '关联的里程碑',
    title             VARCHAR(200)    NOT NULL COMMENT '任务名称',
    description       VARCHAR(1000)   DEFAULT NULL COMMENT '任务描述或AI建议资源',
    scheduled_date    DATE            NOT NULL COMMENT '建议执行日期',
    estimated_minutes int UNSIGNED    DEFAULT 0 COMMENT '预估耗时（分钟）',
    actual_minutes    int UNSIGNED    DEFAULT NULL COMMENT '用户实际耗时',
    quality_score     TINYINT UNSIGNED DEFAULT NULL COMMENT '自评质量 1-5星',
    status            ENUM('PENDING','COMPLETED','SKIPPED') DEFAULT 'PENDING',
    skip_reason       VARCHAR(500)    DEFAULT NULL COMMENT '跳过原因（选项：时间不够/难度过高/临时有事/其他）',
    completed_at      DATETIME        DEFAULT NULL COMMENT '完成时间',
    created_at        DATETIME        DEFAULT CURRENT_TIMESTAMP,
    updated_at        DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    KEY idx_user_scheduled (user_id, scheduled_date),
    KEY idx_goal_scheduled (goal_id, scheduled_date),
    CONSTRAINT fk_tasks_plan FOREIGN KEY (plan_id) REFERENCES plans(id) ON DELETE CASCADE,
    CONSTRAINT fk_tasks_goal FOREIGN KEY (goal_id) REFERENCES goals(id) ON DELETE CASCADE,
    CONSTRAINT fk_tasks_milestone FOREIGN KEY (milestone_id) REFERENCES milestones(id) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='任务表';
```

### 字段说明
| 字段 | 类型 | 说明 |
|:---|:---|:---|
| `plan_id` | BIGINT | 所属计划版本，便于追溯 |
| `goal_id` | BIGINT | 冗余目标ID，方便聚合今日任务 |
| `user_id` | BIGINT | 冗余，直接校验用户权限 |
| `milestone_id` | BIGINT | 关联的里程碑，可空 |
| `title` | VARCHAR(200) | 任务标题 |
| `description` | VARCHAR(1000) | 详细说明或AI推荐的资源链接 |
| `scheduled_date` | DATE | 任务安排在哪天执行 |
| `estimated_minutes` | INT | AI预估耗时 |
| `actual_minutes` | INT | 用户实际耗时，用于反馈偏差分析 |
| `quality_score` | TINYINT | 用户自评完成质量（1-5），可选 |
| `status` | ENUM | 任务执行状态 |
| `skip_reason` | VARCHAR(500) | 跳过时选择的理由 |

## 9. AI调用日志表 `ai_invoke_logs`
记录每一次对AI模型（千问等）的请求详情，用于成本分析、性能监控与问题排查。

```sql
CREATE TABLE ai_invoke_logs (
    id                BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    user_id           BIGINT UNSIGNED DEFAULT NULL COMMENT '调用用户（若为系统触发可为空）',
    goal_id           BIGINT UNSIGNED DEFAULT NULL COMMENT '关联目标',
    invoke_type       ENUM('DECOMPOSE','SCHEDULE','FEEDBACK','OTHER') NOT NULL,
    provider          VARCHAR(20)     NOT NULL DEFAULT 'qwen' COMMENT '模型提供商',
    model             VARCHAR(30)     NOT NULL DEFAULT 'qwen-turbo' COMMENT '具体模型名称',
    prompt            TEXT            DEFAULT NULL COMMENT '脱敏或哈希后的prompt',
    prompt_tokens     INT UNSIGNED    DEFAULT 0,
    completion_tokens INT UNSIGNED    DEFAULT 0,
    cost_cny          DECIMAL(10,6)   DEFAULT 0.000000 COMMENT '预估费用（人民币）',
    status            ENUM('SUCCESS','FAILED') DEFAULT 'SUCCESS',
    response_time_ms  INT UNSIGNED    DEFAULT 0 COMMENT '响应耗时（毫秒）',
    error_message     VARCHAR(500)    DEFAULT NULL COMMENT '失败时记录错误信息',
    created_at        DATETIME        DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    KEY idx_user_time (user_id, created_at),
    KEY idx_status_time (status, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='AI调用日志表';
```

### 字段说明
| 字段 | 类型 | 说明 |
|:---|:---|:---|
| `user_id` | BIGINT | 调用用户ID，系统级触发可为空 |
| `goal_id` | BIGINT | 关联的目标ID |
| `invoke_type` | ENUM | 调用用途：目标拆解、排期、反馈分析等 |
| `provider` | VARCHAR(20) | 提供商标识 |
| `model` | VARCHAR(30) | 具体模型名称 |
| `prompt` | TEXT | 请求的提示词（可存储哈希值以节省空间） |
| `prompt_tokens` | INT | 输入token数 |
| `completion_tokens` | INT | 输出token数 |
| `cost_cny` | DECIMAL(10,6) | 单次调用预估成本 |
| `status` | ENUM | 调用结果成功或失败 |
| `response_time_ms` | INT | API响应时间 |
| `error_message` | VARCHAR(500) | 失败时的错误详情 |

## 10. AI提示词配置表 `ai_prompts`
管理拆解、排期、反馈三类 Prompt 的版本与内容，支持热更新和 A/B 测试。

```sql
CREATE TABLE ai_prompts (
    id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    type        ENUM('DECOMPOSE','SCHEDULE','FEEDBACK') NOT NULL,
    version     VARCHAR(20)     NOT NULL COMMENT '版本号，如v1.0',
    provider    VARCHAR(20)     NOT NULL DEFAULT 'qwen',
    content     TEXT            NOT NULL COMMENT '提示词全文（含占位符）',
    is_active   TINYINT(1)      DEFAULT 0 COMMENT '是否为当前生产环境生效版本',
    is_ab_test  TINYINT(1)      DEFAULT 0 COMMENT '是否参与A/B测试',
    test_group  VARCHAR(10)     DEFAULT NULL COMMENT 'A/B分组标识，如A、B、control',
    created_at  DATETIME        DEFAULT CURRENT_TIMESTAMP,
    updated_at  DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    KEY idx_type_active (type, is_active)
```

## 关系模型概要
- `users` ↔ `user_identities`：一对多，一个用户可绑定多种登录方式。
- `users` ↔ `user_sessions`：一对多，支持多设备登录。
- `users` ↔ `user_notification_settings`：一对一。
- `users` ↔ `goals`：一对多，单用户最多5个ACTIVE目标。
- `goals` ↔ `milestones`：一对多，目标拆解出4-6个阶段。
- `goals` ↔ `plans`：一对多，每次重排生成新版本。
- `plans` ↔ `tasks`：一对多，一个计划包含多个每日任务。
- `tasks` 中冗余 `goal_id`、`user_id` 以加速聚合查询。
- `ai_invoke_logs`、`ai_feedback_records`、`ai_prompts` 为独立支撑模块。
- `admin_users` 与 C 端用户体系完全隔离。

该设计覆盖了 PRD 中前台功能、后台管理、AI 编排闭环的所有持久化需求，同时融合了安全的用户认证实践，可支撑后续功能迭代。
